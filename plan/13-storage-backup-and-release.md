# Storage, backup and release (OPS-01)

## Fresh baseline and configuration

Default data directory: macOS ~/Library/Application Support/Shepherd/v1; Linux ${XDG_DATA_HOME:-~/.local/share}/shepherd/v1. Database shepherd.db, identity files owner-token/replay-key, daemon.lock, backups/. Flags --data-dir, --db, --port, --ui-dir override environment SHEPHERD_DATA_DIR, SHEPHERD_DB, SHEPHERD_PORT, SHEPHERD_UI_DIR, which override defaults. Port 7437. Explicit --db still stores credential files in data-dir. Print resolved nonsecret paths at startup.

Recognize stable DB by application_id=1397248068 plus schema_meta(version=1, export_version=2.0.0). Fresh database initialization is transactional. Existing nonempty database without this identity -> refuse with mvp_database/foreign_database explanation. Never modify the MVP file ~/.shepherd/shepherd.db automatically, delete sqlx migration history, or infer epic ownership. Preserve old file as archive. Subsequent stable upgrades use ordered immutable SQL migrations, pre-upgrade full backup and schema compatibility check; old binaries reject newer schema. Downgrade by restoring backup, not reversing destructive migrations.

## Export/import

Portable export is one consistent read transaction for an entire project. [JSON Schema](contracts/export.schema.json) owns format 2.0.0; current runtime fields/counts/eligibility in exported resources are informational snapshots and recomputed on import. Include all archived data and historical actors referenced by content. Exclude claims, credentials, security audit and domain event stream; sessions retain historical claim UUIDs but these are not active claim references.

Import only exact version 2.0.0 in v1. Portable arrays have no record-count cap: project history can grow beyond the graph/query envelope. Stream export from a read snapshot; stream owner-only import to a temporary SQLite staging database, validating each bounded record and then cross-record invariants, before one atomic merge into the destination. Do not deserialize the entire project into memory. No total HTTP body cap applies to this one authenticated endpoint; per-record schema bounds still apply. Check available staging disk and return 507 insufficient_storage on exhaustion with cleanup/no committed project. A disconnected importer cleans its staging file and rolls back. Never truncate an export to graph-size limits. Validate syntax, IDs/duplicates, referential/project ownership, type registry, both scoped DAGs, review policy/producer rules, content revision sequence and selected/accepted revision links before any writes. Remap every live resource and actor UUID; historical claim IDs in sessions remap to fresh historical UUIDs without claim rows. Preserve dates/history, then reset imported pending submissions to withdrawn with import reason stored in audit; tasks in plan_review/work_review return planning/execution. Claims are never imported. Completed work stays done, cancelled stays cancelled; active tasks keep active but are unclaimed. New imported actors revoked; imported historical reviews retain that identity. Current caller owns the import command. Counts/eligibility recompute; fail import if impossible terminal hierarchy instead of silently reopening. Return complete old/new ID map. Entire import is one transaction, including events; a failed import creates nothing.

## Full backup and restore

Provide local maintenance subcommands on shepherd-server (not REST/agent tools): backup --output <directory>, restore --from <directory>, doctor. Stop daemon before maintenance; refuse when lock held. Open SQLite and run VACUUM INTO a new destination for a consistent DB copy (no shell interpolation; bound/escaped SQL path through library). Copy owner-token and replay-key, create manifest with version, SHA-256 digests and UTC creation time. Output directory 0700, files 0600. Refuse existing output directory. Restore verifies manifest/digests/schema/integrity, copies to staging, then swaps data files while daemon stopped; preserve original in timestamped recovery directory. Never copy a live DB file without its WAL semantics. Full restore preserves credential validity; project import does not.

## Runtime operations

Structured logs: timestamp, level, request_id/command_id, operation, duration, result code; no user document content. Graceful SIGINT/SIGTERM: stop accepting requests, stop sweeper, allow 10 seconds in-flight commands, close pool, release lock. SQLite atomic transactions protect interrupted writes. On startup run quick_check, foreign_key_check and domain consistency checks; on failure expose health fail and doctor output, reject mutation routes with integrity_failure. Never claim automatic repair.

Health checks DB availability/schema compatibility; 503 on fail. doctor reports schema version, integrity issues with resource IDs, expired claims, DB size, resolved paths; no secrets. Periodic sweep errors are logged and do not terminate the daemon; eligibility still checks expiry transactionally. Recovery tests kill process during reports and compare committed state after restart.

## Release artifacts

Targets: aarch64-apple-darwin, x86_64-apple-darwin, x86_64-unknown-linux-gnu (Ubuntu 22.04/glibc 2.35 minimum). Each tar.gz contains bin/shepherd-server, bin/shepherd, bin/shepherd-mcp, share/shepherd/ui/, LICENSE, version.json and installation/backup guide. Server resolves default assets relative to executable ../share/shepherd/ui, never launch working directory. Explicit --ui-dir remains dev override.

CI release builds use existing lockfiles and pinned compiler/Node, build matching UI once, verify all archive checksums, smoke start from unrelated temporary cwd, login, create project/goal/epic/task, query via CLI and MCP, stop, backup, restore, restart. Publish SHA256SUMS alongside archives. No automatic updater, package-manager formula, code signing or notarization in v1; explain platform launch instructions. Version metadata includes application version, export/schema versions and source commit. Do not claim signed distribution.

## Performance acceptance

Synthetic test envelope: 20 projects, 2,000 tasks per project, 10 concurrent agent clients; max rendered scope 2,000 nodes/4,000 edges. Record runner OS/CPU/RAM, warmup and sample count. Target work discovery and paginated read p95 <=300 ms on a 4-vCPU/8-GiB local SSD runner with 1,000 measured requests after 100 warmups. Target graph interactive within 2 seconds in Chromium on same runner; no unbounded DOM/list rendering. These are release targets, not measured MVP claims. If regression fails, profile SQL/query fanout/layout before changing database or framework.
