# 04 — UI & visualization

> The UI is a pure client of the REST API + SSE stream ([03-api.md](03-api.md)). Built in sessions S7–S8.

## Screens

| Screen | Purpose |
|---|---|
| **Project registry** | List/register projects, per-project settings (review gate), export/import |
| **Graph view** | The heart of shepherd — two lenses over the task graph, live |
| **Task detail** | Core fields, metadata, relations, attempt history, sessions timeline, knowledge |
| **Review queue** | Agent-completed tasks awaiting human approval; approve/reject with reason |
| **Project knowledge** | The project-scoped knowledge set + search across all project knowledge |

## The two lenses (deliberately distinct — [02](02-domain-model.md))

- **Decomposition tree** — parent/child: how the big goal splits. Answers *"what is this project made
  of?"*
- **Dependency flow** — `depends_on` DAG, laid out start → end. Answers *"what was done, what's next,
  what's blocked on what?"*

Shared visual language across both: status is color/shape-coded (`proposed` dashed, `ready` highlighted,
`in_progress` with claimant identity badge, `in_review` flagged for the human, `done` dimmed, `blocked`
warning, failure-count badge on tasks with failed attempts). Selecting a node opens task detail.

## Liveness

The graph subscribes to the SSE stream and updates in place — an agent claiming, reporting, or proposing
is visible as it happens. On reconnect the client refetches (no event replay in v1).

## Post-project review

The same graph, read as history: walk the flow start → end, open any task's sessions and decisions,
follow knowledge items to their source. No dedicated "report" feature in v1 — the graph + task detail
*is* the review.

## Theming

Light and dark themes, resolved from the OS preference with a manual
light/dark/system override persisted in the browser. All colors — including
the status language — flow through the custom properties in
`ui/src/styles/tokens.css`; `data-theme` on `<html>` always holds the
resolved theme.

## v1 non-goals

Mobile layouts, accessibility audits (axe checks are a post-v1 test item —
[05](05-testing.md)), collaborative/multi-user views, graph editing beyond task/relation CRUD.

## Open decision (S8)

Graph rendering library — React Flow vs lighter alternatives — decided under the minimal-dependency rule
when the graph view is built, with the decision recorded in the session issue.
